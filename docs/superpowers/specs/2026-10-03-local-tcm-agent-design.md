# 本地中医穴位参考 Agent 设计规格

日期：2026-10-03  
状态：已完成交互讨论，等待用户复核书面规格

## 1. 项目目标

从零构建一个可直接双击 `index.html` 运行的中文网页。网页面向个人日常参考，通过逐步选择身体部位和常见轻微不适，返回简洁的穴位信息。

第一版是完全离线的规则型产品原型，不使用大语言模型、后端服务、网络请求、用户账号或数据上传。界面入口沿用用户指定名称“在线问诊”，但必须同时标明“本地运行、仅供参考”，避免让用户误以为这是远程医生诊疗服务。

## 2. 安全定位

本产品是健康知识参考工具，不提供医学诊断，不替代医生，不承诺疗效，也不针对急症、严重症状或复杂疾病提供穴位治疗建议。

- 问诊开始前展示醒目的危险症状说明。
- 出现胸痛、呼吸困难、突然偏瘫或意识异常、高热不退、孕期异常等危险情况时，应停止自助流程并提示立即就医或联系急救。
- 普通结果页固定显示：“仅供日常健康知识参考，不构成诊断或治疗建议。”
- 第一版知识内容在公开发布前必须由具备资质的中医专业人员复核。
- 网页不要求姓名、联系方式或病史；用户当次选择只存在页面内存中，不写入本地存储，也不上传。

## 3. 已确认的用户体验

### 3.1 首页

首页采用主次分明的双入口布局：

1. “在线问诊”为主要入口，视觉权重更高。
2. “产品介绍”为次要入口，第一版显示结构化占位内容，后续由用户提供正式产品信息后替换。

首页包含简短产品主张、“本地运行 · 隐私优先”提示和安全声明。当前原型中的“岐黄小助”只是临时展示名称，不作为正式品牌名。

### 3.2 在线问诊

问诊采用逐步引导，而不是自由文本聊天：

1. 用户进入问诊页并阅读安全说明。
2. 第一步选择主要不适部位：头面部、肩颈与上肢、胸腹与消化、腰背与下肢。
3. 第二步从该部位下选择一种预置的常见轻微不适。
4. 结果页显示 1–3 个相关穴位，每个穴位只包含名称和一句话定位。
5. 用户可返回上一步修改选择，或重新开始问诊。

未选择项目时，“下一步”按钮保持禁用。页面刷新后回到首页，不保存问诊状态。

### 3.3 产品介绍

产品介绍与问诊是并列支线。第一版提供可替换的版块骨架：产品理念、主要能力、隐私方式、适用范围和使用边界。正式文案和品牌资源不在本次基础框架范围内。

## 4. 技术方案

采用无构建工具的单页多视图架构，确保用户可以直接双击运行：

```text
index.html
styles.css
data.js
app.js
assets/
```

- `index.html`：语义化页面结构、首页、问诊、结果和产品介绍的视图容器。
- `styles.css`：视觉系统、组件样式、响应式布局、焦点状态和轻量过渡动效。
- `data.js`：身体部位、症状、穴位、安全提示和它们之间的关系。
- `app.js`：视图切换、步骤状态、用户选择、结果生成、返回和重新开始。
- `assets/`：后续加入的品牌图片或插画；第一版不依赖远程资源。

所有脚本使用传统 `<script>` 加载，不使用 ES Module、`fetch()` 或客户端路由框架，以避免 `file://` 环境中的跨域与模块加载限制。

## 5. 数据设计

数据以只读 JavaScript 对象保存，并暴露给页面脚本。核心实体如下：

- `bodyRegions`：部位 ID、显示名称、图标标识和关联症状 ID。
- `symptoms`：不适 ID、显示名称、所属部位和关联穴位 ID。
- `acupoints`：穴位 ID、名称、一句话定位和必要的简短禁忌提示。
- `safetyNotices`：全局免责声明、危险症状说明和异常回退文案。

初始内容规模为 4 个身体部位分类、约 12 种常见轻微不适和约 15 个常用穴位。具体医学内容在实现时作为待专业审核的数据集处理；界面架构不依赖某一条具体医学结论。

## 6. 页面组件与状态

页面由以下职责清晰的组件区域组成：

- 顶部品牌栏：品牌占位名称、本地运行标识、返回首页入口。
- 首页主视觉：产品主张与两个入口卡片。
- 安全提示板：问诊前必须阅读的使用边界与危险症状。
- 步骤指示器：显示当前步骤和进度。
- 选项网格：渲染身体部位或具体不适，支持键盘选择和清晰焦点状态。
- 结果卡片：渲染穴位名称、定位和统一免责声明。
- 产品介绍视图：渲染可替换的介绍版块。

应用只维护少量内存状态：当前视图、已选部位、已选不适。状态不会写入本地存储。

## 7. 数据流

```text
首页
 ├─ 产品介绍 → 展示占位版块 → 返回首页
 └─ 在线问诊 → 安全说明
                 → 选择身体部位
                 → 按部位筛选具体不适
                 → 按不适查找 1–3 个穴位
                 → 展示结果与免责声明
```

渲染层只读取数据并发出选择事件；状态控制逻辑负责校验选择和决定下一个视图；数据文件不包含界面操作代码。

## 8. 错误与边界处理

- 没有选择时不能进入下一步。
- 部位下没有症状时，显示“内容尚未收录”，允许返回选择其他部位。
- 症状没有关联穴位或数据 ID 无效时，不猜测结果，显示安全回退信息并允许重新开始。
- 数据脚本未成功加载时，展示静态错误说明，而不是空白页面。
- JavaScript 不可用时，首页仍展示产品定位、产品介绍摘要和安全声明，但问诊入口明确提示需要启用脚本。
- 长文本、窄屏和系统字体放大不应造成按钮遮挡或内容溢出。

## 9. 视觉方向

采用已确认的首页方案 A：温和的米色纸张背景、低饱和草木绿色、深墨绿色主按钮和克制的暖色警示。整体为现代中式，而非仿古装饰风格。

“在线问诊”卡片使用更深的主色和更大的面积；“产品介绍”卡片保持浅色。问诊选项以大触控卡片呈现，移动端单列或双列自适应。动画只用于视图淡入和进度变化，并遵守系统的减少动态效果设置。

## 10. 可访问性与响应式

- 使用原生按钮和标题层级，不能只依赖 `div` 点击。
- 所有交互支持键盘操作，并提供可见焦点样式。
- 文本和背景达到清晰可读的对比度。
- 关键状态不只依赖颜色表达。
- 适配约 360px 宽的手机屏幕到桌面屏幕。
- 尊重 `prefers-reduced-motion`。

## 11. 验证计划

实现完成后至少验证：

1. 在无开发服务器的情况下双击 `index.html`，所有本地资源和功能可用。
2. 首页两个入口均可进入并正确返回。
3. 四个部位分类均能进入第二步；有数据时可得到对应结果。
4. 未选择时不能继续，缺失数据时出现安全回退而非报错。
5. 重新开始会清空选择并返回问诊第一步。
6. 普通结果页、安全说明和产品介绍页均展示正确的使用边界。
7. 使用键盘可完成全部路径，焦点顺序合理。
8. 在手机与桌面宽度下检查布局、字体放大和长文案。

## 12. 本次范围之外

- 本地或云端大语言模型。
- 自由文本症状理解、诊断推断和个性化治疗方案。
- 用户账号、病历、收藏、历史记录和数据同步。
- 后端数据库、联网检索、API 或管理后台。
- 人体穴位图、摄像头识别、语音输入和多语言。
- 正式产品介绍文案、正式品牌名和品牌视觉资源。
